- **2026-10-31, building on GitHub: measured, not decided.** Alex asked whether the firmware could be
  built there, Vivado downloaded on the fly, for free because the repository is public. Public
  repositories do get the standard runners for nothing, and artifacts and release assets as well, but
  the bitstream cannot run on them: a standard runner has 4 vCPU, 16 GB RAM and 14 GB of disk, while
  Vivado 2024.1 needs 30-50 GB installed for Artix-7 alone; the Actions cache is capped at 10 GB per
  repository, so the installation cannot be cached and would be fetched again every run; and the
  download needs an AMD account, while putting our `vivado-env:2024.1` image on a public registry would
  be redistributing AMD's tools. What *can* run there today: `lint`, `app` and `sims`. The application
  is built with `riscv32-unknown-elf-gcc` (`ci/app.sh`), a plain GCC cross toolchain, and the simulation
  image is `ubuntu:24.04` plus the OSS CAD Suite (`ci/sim/Dockerfile`), so both may be published.
  The ROMs the application links are at the same paths in Gideon's repository, which is on GitHub
  (Alex: "Die ROMS sind auch alles schoen bei Gideon auf github, da muss man nicht mal raus"), so a
  workflow fetches them and nothing leaves the platform. The bitstream would need a self-hosted runner,
  i.e. our builder, and a public repository with a self-hosted runner means a stranger's pull request
  runs code on it - only with approval for every outside contributor, an ephemeral runner, no secrets on
  it and its own network segment. Not decided.
