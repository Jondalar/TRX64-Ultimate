# T46: Release build switch: leave out jtag_dbg

Milestone M3, status ✅. Open (one line, as in the TODO table): -

Decisions: [ADR-0020 Release/RC without JTAG debug](../adr/0020-d04-release-without-jtag-debug.md).

## Description

Release build switch: leave out `jtag_dbg` (dev access, about 480 LUT, docs/lut-budget.md); debugging a release board = dev bitstream in SRAM

See also: [docs/lut-budget.md](../lut-budget.md)

## Status and history

Moved from the TODO.md row on 2026-10-07, wording unchanged. Dated entries, newest first; undated text stays attached to the entry before it.

- **2026-11-13, built (Alex: "Schmeiss es raus", for U13's room).** As in the MultiCore host: `top.v` has
  `` `ifdef NO_JTAG_DBG `` around `jtag_dbg` (its outputs tied to 0), `build.tcl` defines it unless the environment's
  `TRX_FEATURES` lists `jtag`, and `gateware_key` (ci/lib.sh) carries `features=`. The default build, CI's too, has no
  JTAG debug master: the debug registers, the console and keyboard-edge read-out, the RISC-V tap and the JTAG ports into
  DDR2, the C64 RAM and the trx registers fall away with it (about 850 LUT in run 1318's report: `jtag_dbg` 707 with its
  read mux, `con_ring` 97, `rv_dbg` 38; more than the 480 measured on 2026-10-03). The registers JTAG writes
  (`machine_ctl`, `ddr_window`, `i2c_ovr`, `mdio_ovr`, `usb_ctl`, `iec_port_off`) keep their power-up values of 0, the
  values the machine runs with. A softload does not use it: the MultiCore host starts a `.cfw` through the ICAP and
  hands the app over in DDR2 (`CFW_BOOT_MAGIC` at 0xFFFC, host-app `cfw.h`), which the boot ROM checks first.
  `tools/trxdbg.sh` (boot over JTAG, console, memory) and the board scripts under `tests/` that call it (21 files)
  need a dev build: `TRX_FEATURES=jtag`.
